# Gear 2 · 深度工程攻坚流（1 → N：已知系统内的硬骨头）

适用于根因隐蔽、多路径架构权衡、跨模块/跨上游仓库耦合、历史反复修补未果，或具有严格性能/精度/稳定性要求的攻坚任务。全程通过 Paseo 显式调度 **`[Explorer]`、`[Red-Team]`、`[Worker]`、`[Reviewer]`** 四类子会话协同，并同步挂载对应 `lens-*.md` 硬约束卡。

---

## 前半段：多 Agent 正交探源、异构红队证伪与人机拍板

### Step 1 · 事实与不变量锚定（Coordinator / `[Triage]` 只读）

只建立客观事实基线，不出拍脑袋方案：

- 梳理真实运行链路、数据流/状态机现状、历史相关提交或曾撤回的失败实验，并在 `$PASEO_HOME/runs/<task-id>/status.md`（缺省 `~/.paseo/runs/<task-id>/status.md`）初始化运行账本。
- 明确不可破坏的**核心不变量（Invariants）**与专项卡要求的定量基线/分母，重述真正要解的核心矛盾。

### Step 2 · 正交三范式并行探源（Paseo `[Explorer]` 只读子会话）

对跨模块或高复杂度问题，通过 Paseo 并行启动 2～3 个只读 `[Explorer]` 子会话（标题如 `[Explorer-A] Incremental`、`[Explorer-B] Structural`、`[Explorer-C] Boundary-Shift`；跨模型并行时控制使用不超过 `N-1` 个可用模型家族，确保留出至少 1 个异构家族供红队使用），沿三个正交范式发掘解空间：

- **范式 A · 渐进/局部路径**：最小变更半径，复用现有扩展点与机制，风险最低但须核算理论上限。
- **范式 B · 结构/模型路径**：重构数据结构、索引、状态机或职责抽象，从机制上消除整类问题而非逐点特判。
- **范式 C · 边界外移/消解路径**：跳出当前模块——检查能否在输入生产端、内部上游二方依赖库（必要时反编译或拉取上游源码）、构建工具链或协议层直接消解复杂度。

### Step 3 · 跨模型异构红队证伪（Paseo `[Red-Team]` 只读子会话）

协调官汇总候选方案后，启动**与各候选方案作者 `[Explorer]` 不同模型家族的只读 `[Red-Team]` 子会话**，传入候选方案与最新源码路径，唯一职责是“挑刺证伪”：

1. **前提真伪与查重**：依赖的代码假设是否真实成立？最新主干是否已有等价实现或冲突逻辑？
2. **漏口与反例构造**：全仓搜索绕过该方案的隐藏入口、锁序反转、缓存失效遗漏、异常/降级吞咽或缺失依赖（`Phantom`/未解析符号）退化陷阱。
3. **收益-复杂度拷问**：真实端到端效果是否配得上引入的维护负担？（淘汰低上限补丁与过度工程化抽象。）
4. **未知假设探针验证（不增加人工停顿）**：若某方案卡在静态看代码无法定论的单一运行时假设上，协调官可直接创建临时隔离 worktree 派 1 个 `[Worker]` 跑一次 10 分钟级可丢弃微探针取证（不进入 [mode-explore-spike.md](mode-explore-spike.md) 的人工停顿流程），将实测事实直接喂入 Step 4。

### Step 4 · 权衡收敛与人机拍板（全流程唯一默认停顿点）

- 协调官淘汰被证伪方案（保留一句话淘汰原因），输出幸存方案对比表：**根源位置（含跨仓说明） | 核心机制 | 预期收益上限 | 红队已排雷边界与 Trade-off**。
- **停顿与用户探讨拍板**本轮实施切片（若用户已授权全自动推进则记录依据直通；若证伪后发现实为简单漏配则降回 Gear 1）。

---

## 后半段：Paseo 独立 Worktree 隔离开发与异构双审闭环（拍板后自动推进）

### Stage 1 · 双视角异构方案预审（2 个并行 Paseo `[Reviewer]` 只读子会话）

动代码前编写可证伪实施规格（不变量、反例清单、精确文件范围、验证口径），通过 Paseo 并行启动两个独立只读预审会话（至少其一与后续 `[Worker]` 跨模型家族）：

- **`[Reviewer-Pre-A]`（语义与不变量视角）**：审业务/分析语义守恒、状态生命周期、并发安全、异常与退化守恒、兼容性。
- **`[Reviewer-Pre-B]`（可验证性与隔离视角）**：审反例测试能否真正拦截错误实现、worktree 与本地依赖缓存零污染方案、实证对比口径公平性。
- **准入门禁**：全部带实证的 `BLOCKING` 项收敛进修订版规格并更新 `status.md` 后，才切分开发 worktree。

### Stage 2 · 独立 Worktree 并行实现与反例先行（Paseo `[Worker]` 隔离会话）

- 协调官记录主工作区未提交内容哈希 `MAIN_DIFF_HASH`，按正交子切片创建独立分支与物理目录（`git worktree add -b <slice> <worktree-path> <BASE_SHA>`，设 `SLICE_BASE = BASE_SHA`，若依赖未提交补丁则先单独提交为前置 `SLICE_BASE`；凡涉及写入包缓存或修改二方库均配置独立本地缓存目录），用 `--cwd <worktree-path>` 绑定启动 `[Worker]`（并发写会话默认 ≤ 2 个）。
- **实证退单权**：`[Worker]` 先验证根因假设，若动态实证推翻假设则立即停工退回协调官调整方案。
- **反例测试先行与干净提交**：除常规回归外，`[Worker]` 必须将 Step 3 与 Stage 1 识别的全部边界陷阱写成自动化反例单测并在隔离分支内跑绿（重型测试按宿主机负载串行执行），最后在隔离分支完成干净的本地 Git 提交。

### Stage 3 · 双视角异构代码后审、实证审计与无冲突串行合入

- **异构双视角后审（禁止自审代替他审）**：协调官核验主工作区 `MAIN_DIFF_HASH` 未变、隔离 worktree 无未提交脏文件且 `<SLICE_BASE>..HEAD` 有提交并记录 `WT_HEAD_SHA` 后，并行启动**与 `[Worker]` 不同模型家族**的两个只读后审会话，直传隔离 worktree 路径、`git diff <SLICE_BASE>...HEAD` 与测试日志（审毕再次核验 `WT_HEAD_SHA` 未被篡改）：
  - **`[Reviewer-Post-A]`**：逐行审完整 diff 的语义等价性、并发/锁序与边界退化；
  - **`[Reviewer-Post-B]`**：审反例测试真实覆盖度、构建产物条目级纯净度及主工作区/全局缓存零污染。
  - 若有带反例的 `BLOCKING` 缺陷，派回原隔离 `[Worker]` 修复提交，并由**同一异构 `[Reviewer]` 同时复核增量修复与完整 `git diff <SLICE_BASE>...HEAD`** 直至 `0 BLOCKING`（满 2 轮仍修不好确凿缺陷则退回重诊或丢弃该候选切片，严禁带有效 `BLOCKING` 合入）。
- **受控实证对比与独立数据审计**：按所挂 `lens-*.md` 执行前后实证对比；涉及基准测量或大规模对比数据时，另派独立只读 `[Reviewer-Audit]` 复核原始日志与统计计算。
- **无冲突串行合入或干净丢弃**：全部门禁通过后，由**协调官**执行 `<SLICE_BASE>..HEAD` 无冲突串行合入（若多切片冲突，退回后合入切片原 `[Worker]` 在隔离树内 `rebase` 到新目标顶端并更新 `SLICE_BASE`、重跑测试并经原异构 `[Reviewer]` 对新 `git diff <SLICE_BASE>...HEAD` 复审通过后再合入），在最终合并树上重跑集成验证并清理临时 worktree；若实证未达门槛，先完整归档证据，再直接删除隔离 worktree 与临时分支。
