# 重构与架构演进专项卡（Refactor & Architecture Lens）

处理核心模块解耦、数据结构替换、多轨历史逻辑收敛单轨、公共接口演进或跨层职责迁移时强制挂载。

## 1. 显式与隐式依赖全盘点

动手拆分或替换前，除常规编译期调用链外，必须排查四类隐式耦合：

1. **动态机制**：反射调用、序列化/反序列化字段名、注解处理器、SPI / 依赖注入配置；
2. **数据与外部契约**：持久化格式、CLI 参数、环境变量、日志/报告解析脚本、上下游仓库依赖版本；
3. **并发与生命周期**：初始化顺序、单例/线程局部状态清理时机、异常回滚语义；
4. **测试桩耦合**：既有测试是否直接依赖了旧内部类或调用计数断言。

## 2. 单轨收敛与迁移半径控制

- **拒绝永久双轨泥潭**：优先采用小步、可独立验证的切片完成迁移，并在验证等价后**彻底清理废弃旧路径与死代码**；不留无人维护的平行旧实现。
- **受控过渡开关**：仅当爆炸半径过大确需保留特性开关时，必须明确默认行为、新旧切换边界及明确的旧轨退役条件。
- **契约与功能变更分离**：纯结构重构批次严格保持外部可观察行为不变，避免将“结构搬迁”与“新业务规则修改”混在同一不可拆分的巨型 diff 中导致回归难以归因。

## 3. 可观察行为等价基线

- 重构前锁定受影响范围的行为基线（公开 API 契约、端到端输出快照、错误/诊断行为及关键性能水位）。
- 重构后执行全量受影响回归与快照对比；凡存在预期的行为差异或废弃项，必须在方案预审与交付报告中逐条显式列出。
