# 性能专项硬约束卡（Performance Lens）

处理耗时优化、吞吐提升、内存/RSS 压降、GC 或锁竞争治理等性能任务时强制挂载。性能优化最易受测量噪声、分母错觉与隐性降级误导，全流程须严守以下硬杠杠：

## 1. 端到端真分母与 Amdahl 上限先行

- **拒绝分母幻觉**：动手前必须基于真实端到端阶段日志或完整采样数据，算清目标环节占**总墙钟耗时（Wall Time）**或**总存活内存/峰值 RSS** 的真实分母。
- **区分采样与计时**：CPU 火焰图宽度代表采样栈权重而非直接可省墙钟秒数；分配火焰图（TLAB/对象分配速率）不等于 GC 后常驻存活堆或进程峰值 RSS。
- **Amdahl 淘汰线**：折算到端到端全局后，若候选方案的理论极限收益低于噪声带（如常规 `<5%`）却显著增加核心代码复杂度，在探源/红队阶段直接淘汰，不投入实现。

## 2. 缓存、索引与并发状态证明

- 引入任何新缓存、预筛索引或增量结构前，必须完整证明四件事：
  1. **键与对象身份**：按值相等还是按实例身份？是否意外延长大对象生命周期导致内存泄漏？
  2. **失效完备性**：全仓（含上游依赖库、懒加载、动态生成/反射）有哪些路径会修改底层事实？失效或增量更新是否覆盖了全部入口？
  3. **异常与重试守恒**：首次加载失败、缺失依赖（如 Phantom/未解析符号）或异常回退时，是否保持与原路径完全一致的诊断计数和重试机会？
  4. **锁序与可见性**：多线程读写是否存在锁顺序反转死锁或非原子发布竞态？

## 3. 构建产物纯净度核验

- 跨模块或修改上游二方依赖包时，使用独立本地依赖目录构建，严禁覆盖污染全局共享缓存（如 `~/.m2`）。
- 正式测量前核验候选运行包与基线运行包的条目级差异（如 JAR/ZIP entry diff）：除本次预期修改的类簇（含内部类/匿名类）外，不得出现意外的类遮蔽、漏包、编译器版本漂移或依赖变动。

## 4. 受控基准测量与控制变量隔离

- **锁定控制变量**：基线组与候选组必须使用完全相同的冻结输入、运行时版本、内存参数、线程数与打包形态。
- **物理防干扰**：正式计时与重负载编译/全量单测严格互斥；使用文件互斥锁串行执行测量，优先固定 CPU 亲和性（如 `taskset`/NUMA 绑定）并记录宿主机背景负载。
- **正式计时禁挂重采样器**：高开销剖析器/跟踪器仅用于独立诊断轮，不混入正式墙钟/RSS 验收计时。

## 5. 输出与降级零漂移 + 独立数据审计

- **严禁以削弱语义换速度**：不得通过删减规则/功能、放宽超时提前中止、吞掉异常或跳过边界分支来虚增速度（除非用户明确授权做有损权衡并单列精度指标）。
- **全量等价核验**：对比完整输出结果多重集（而非仅比总数或退出码 `0`）以及全部内部错误、超时、降级诊断计数。
- **独立数据终审与失败撤回**：关键基准测试完成后，委派独立只读 Agent 复核原始日志、时间戳、资源曲线与等价性计算；若未达到预期性能门槛或引入内存/质量回退，先完整归档实验数据，再将代码与制品干净恢复基线。
